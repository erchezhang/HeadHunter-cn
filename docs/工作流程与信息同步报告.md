## 1. 插件概况

HeadHunter 是一个 PvP"悬赏通缉"插件：记录击杀你的敌方玩家，把死亡报告在同阵营玩家之间共享，20 分钟内击杀 4 人的敌人会被标记为 WANTED，所有人可在主窗口、地图与鼠标提示上看到同一份名单；击倒通缉犯后全局销案。

模块按 TOC 顺序加载（`HeadHunter.toc`）：

| 层 | 目录 | 职责 |
|---|---|---|
| 本地化 | `Locales.lua` | 所有可见文案的唯一来源，`ns.L` 集中管理 |
| 核心 | `Core/` | 初始化、事件总线、数据库（SavedVariables `HeadHunter_DB`）、守卫（副本内挂起）、命令、模拟工具 |
| 检测 | `Detection/` | 战斗日志/死亡事件 → 死亡报告（`HH_DEATH_RECORDED`）、敌方缓存、分层、职业分类 |
| 同步 | `Sync/` | 线格式、传输、报告校验、追赶、正法、决斗、悬赏、在线计数、官网数据导入 |
| 规则 | `Rules/` | 由报告集派生 WANTED、徽章、赏金积分、决斗排名（可重算、顺序无关） |
| 提醒 | `Alerts/` | 目击、活动、热点、正法等中屏/聊天提醒与追捕队 |
| 赛事 | `Tournament/` | 古拉巴什竞技场赛事（创建、签到、对阵） |
| 界面 | `UI/` | 主窗口、通缉令、地图标记、小地图按钮、鼠标提示、设置页、悬赏/赛事对话框 |

## 2. 界面部分的中文化（本次改动）

### 2.1 文案架构

- 全部 UI 文案集中在 `Locales.lua`：`L = setmetatable({}, { __index = ... return key end })`，缺失键原样回退为键名（显示英文而不是报错）。
- `UI/*.lua` 没有任何硬编码英文文本（已全量检索 `SetText("...")` 等模式，0 命中），一律通过 `ns.L` 取值，包括动态键：
  - `L["TAB_" .. tab]`、`L["EMPTY_" .. tab]`、`L[column.header]`、`L[option.label/ tip/ section]`
  - `L["TOUR_STATUS_" .. status]`、`L["TOUR_BRACKET_" .. b]`、`L["TOUR_BUTTON_" .. action]`、`L["BOUNTY_ERR_" .. why]`
- 原文件没有任何 `GetLocale()` 分支（只有 enUS 默认表），因此中文化以**追加 zhCN 覆盖块**的方式实现，不改动原有英文串。

## 3. 信息同步方式分析

HeadHunter 自身**不发起任何网络请求**（WoW 插件无法联网）。信息同步分两条通路：**游戏内玩家间同步**（addon message）与**经桌面应用到官网的同步**（HeadHunter Sync）。

### 3.1 线格式（`Sync/Protocol.lua`）

- 每条 addon message ≤ 255 字节，只承载**一种类型**的记录：
  `"1" <阵营 A|H> <类型字符> ":" record ("~" record)*`
- 记录内字段用 `;` 分隔，子字段用 `,`；数字用 base36；版本非 `"1"` 直接忽略（前向兼容）。玩家名键禁止含 `;,~|:`，不会与分隔符冲突。
- 职业、种族、置信度压成单字符代码；WoW Forever 的"Skyborne"种族编码同时携带阵营（`K/Y/Q`）。
- 消息类型（16 种）：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| `D` | 死亡报告 | `G` | 身份补全 |
| `Q` | 追赶询问 | `S` | 追赶快照 |
| `J` | 追捕队加入 | `P` | 热点 ping |
| `K` | 正法通报 | `O` | 追赶提议 |
| `U` | 决斗记录 | `V` | 赛事广播 |
| `T` | 连通性测试 | `N` | 在线状态 |
| `B` | 支援响应 | `W` | 悬赏海报 |
| `R` | 悬赏支付 | | |

### 3.2 传输层（`Sync/Transport.lua`）

**发送侧（outbox → 打包 → 令牌桶 → 路由）**

1. `Transport:Queue(type, record, priority, coalesceKey)`：记录进发件箱，相同 `coalesceKey` 覆盖合并（同一目标只留最新）；队列上限 200，溢出时丢**优先级最低且最旧**的记录。
2. 优先级：`alert(1) > posse(2) > hotspot(3) > bulk(4)`。
3. 定时冲刷：每 3 秒（战斗中 10 秒）一次；令牌桶突发 4 条、持续每秒 1 条；同类记录打包成尽量少的消息。
4. 路由按冲刷时的实际可用性选择（`AutoRoutes`）：
   - **WoW Forever**：优先隐藏自建频道 `HeadHunterSync`（跨服务器/跨区域），失败或未加入时回退 `GUILD`、`RAID/PARTY`。
   - **Classic Era**：实测自建频道拒收 addon message（结果码 4 `InvalidChatType`），启动即记为 `channelRefused`，自动路由只剩 `GUILD` + `RAID/PARTY`。
   - **全服范围（仅 Era）**：必须由硬件事件触发——死亡后的 **Report** 按钮 / `/hh report`、正法后的 **Announce** / `/hh justice`、`/hh catchup`——以频道**纯文本**发送，前缀 `HH1:`，每次点击最多 2 行；频道内 join/leave/正文均被聊天过滤器隐藏。
5. `SendDirect`：追赶数据走**插件密语**（`WHISPER`）点对点发送，上限 150 条，失败（对方下线）直接丢弃不重试。
6. 副本内（`Guards:IsActive()` 为假）一律不发。

**接收侧（inbox）**

- `CHAT_MSG_ADDON`（前缀 `HeadHunter`）与 `CHAT_MSG_CHANNEL`（`HH1:` 文本）汇入同一 `Receive`。
- 过滤：发送者名不可读→丢弃；是自己→忽略；解析失败→ `dropped++`；**异阵营消息默认拒收**，仅 `U` 决斗、`T` 测试、`N` 在线、`R` 悬赏支付四类放行（原因：决斗榜含双方阵营、老赖需要跨阵营猎杀）。
- 事件处理器只把记录塞进收件箱，`C_Timer.After(0)` 后按**每帧 3ms 预算**逐条派发给各类型 handler，避免卡帧。

### 3.3 触发时机（谁在什么时候发消息）

| 数据 | 触发 | 类型/优先级 |
|---|---|---|
| 自己的死亡报告 | `HH_DEATH_RECORDED`（`Detection/EraDeaths` 战斗日志 + `PLAYER_DEAD`；Forever 用 `PLAYER_DEAD`+线索）→ `Reports:Add` 成功即广播 | `D` / alert |
| 敌人身份补全 | 本地缓存解析出只知名敌人（`HH_ENEMY_RESOLVED`）→ 通知同伴 | `G` / bulk |
| 正法（击倒通缉犯） | 战斗日志判定 → 本地 `HH_JUSTICE_ADDED` + 广播；同伴收到 `K` 后同样触发 `HH_JUSTICE_ADDED` | `K` |
| 悬赏发布/领取/支付 | 发布海报、领取赏金、邮寄付款事件 | `W`、`R` / alert（Era 发布时同时全服文本） |
| 追捕队 | 玩家点击"加入追捕队" | `J` / posse |
| 热点 | 同区域死亡聚集（监听 `HH_REPORT_ADDED`）→ 计算热度后 ping；点"支援"后回执 | `P`、`B` / hotspot |
| 决斗 | `CHAT_MSG_SYSTEM` 判定胜负 + 目标/鼠标悬停取等级 | `U`（跨阵营允许） |
| 赛事 | 创建/报名/签到/取消等状态变化 | `V` |
| 在线计数 | 登录 30 秒后首发，之后每 600 秒重发（期间收到过别人广播则顺延）；1500 秒内听到即算在线，上限 500 显示"500+" | `N` |
| 追赶 | 登录后延迟启动；或玩家点击 Catch up | `Q`/`O`/`S` |

### 3.4 校验、去重与冲突处理（`Sync/Reports.lua`）

死亡报告集 `ns.db.reports` 是**只增集合**（键 = `<受害者键>:<时间>`）：

1. **发送者必须是受害者本人**（不能替别人报死亡）；
2. **时间合理**：不得超前本机 300 秒，不得早于 30 天；
3. **每发送者限流**：600 秒窗口内至多 10 条；
4. **去重**：同 id 直接忽略；总容量 5000 条，超限按时间淘汰，超过 30 天清理；
5. 身份补全（`G`）只有该报告的受害者本人可以提交；
6. **冲突解决不是"合并字段"，而是"重算"**：报告永不修改（除补全敌人身份），WANTED、等级、徽章、赏金全部由报告集按规则推导，因此**记录到达顺序无关紧要**，天然幂等；收到新报告/补全/正法时 `Wanted:RequestRecompute()` 防抖 1 秒后重算。
7. 追赶转发的报告（origin `relay`）取信于转发者，但时间校验照常。

### 3.5 登录追赶（`Sync/CatchUp.lua`）——离线期间的补齐

1. 计算 `since = 上次登出时间 − 余量`（刚 `/reload` 或已有更新的官网数据则跳过）；
2. 延迟后广播 `Q "hello"`（自动路由；Era 有点击时可全服文本）；
3. 有记录的同伴按在线人数比例、随机延迟回复 `O "N 条"`（插件密语），收集数秒后选**条数最多**者；
4. 向其发 `Q "p<since>"`，对方回 `S` 快照分片（以 `E<条数>` 结束），超时则结束；
5. 结果记录到 `/hh catchup` 输出。Era 上自动 hello 只到公会/队伍，长时间离线会弹出"Catch up"点击框做全服询问。

### 3.6 与官网的同步（第三方通路）

- 桌面应用 **HeadHunter Sync**（独立程序，非插件）在游戏存档时（登出/`/reload`/退出）**读取 SavedVariables `HeadHunter_DB`**，上传到 `headhunterwow.com`；插件本身不联网。
- 下行数据由应用写入**独立插件 `HeadHunter_Data`**（`OptionalDeps`，先于本插件加载），其 `Data.lua` 设置全局表 `HeadHunter_SiteData`（`format_version = 1`，含 `worlds["era|eu|Firemaw"] = { wanted, duels, deadbeats, bullies }`、`characters` 等）。
- `Sync/SiteData.lua` 按"客户端+区域+服务器（Forever 按服务器类型）"选出本世界数据，然后：
  - 把官网 WANTED/决斗榜交给 `Rules/Wanted.lua MergeSite`、`Rules/HighNoon.lua Merge` 与本地所见合并；
  - 恢复本人的死亡/决斗/击倒/赏金事件，标记 `origin = "website"`，**避免应用重复上传**；
  - 登录 10 秒后提示"你被对方阵营列入通缉"（这是唯一能得知跨阵营通缉的途径，因为敌方插件消息不会被信任）。
- 数据按服务器隔离：PvP/普通/角色扮演/硬核（以及每个 Era 服务器）各自一份榜单。

### 3.7 端到端工作流程（一条死亡报告的一生）

```
① 检测     战斗日志/PLAYER_DEAD → Detection/EraDeaths|ForeverDeaths
           → DeathReports 组装报告 → Fire HH_DEATH_RECORDED
② 本地入库 Reports:Add(origin=local)，提示"被 X 击杀"
③ 规则重算 Wanted:RequestRecompute → 4 条/20 分钟 → 上通缉、升阶、打徽章
④ 同步出站 Transport:Queue(D, …, alert) → 3s 冲刷 → 令牌桶
           → addon message：Forever 走隐藏频道，Era 走公会/队伍
             （Era 全服范围需点击 → HH1: 频道文本）
⑤ 同伴入站 Receive → 过滤/限流/校验(发送者=受害者) → inbox(3ms/帧)
           → Reports:Add(origin=peer) → ③ 规则重算（同一条链）
⑥ 呈现     Alerts（目击/活动提醒）+ UI（主窗口/通缉令/地图/鼠标提示）刷新
⑦ 销案     我或队友击倒通缉犯 → HH_JUSTICE_ADDED + 广播 K → 所有人同时销案
⑧ 上行     存档时 HeadHunter Sync 应用读 HeadHunter_DB → 官网
           官网榜单 → HeadHunter_Data → SiteData 合并回游戏（下一次登录生效）
⑨ 补齐     登录追赶 Q/O/S 把离线期间的报告补进本地集合
```
